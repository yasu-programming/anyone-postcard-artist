# 投稿機能 要件定義

## 目的

ユーザーがラジオネームと投稿内容を送信できる最小機能を定義する。
この機能は、審査機能・番組生成機能・音声読み上げ機能の入口になる。

## スコープ

- ユーザーが投稿フォームから内容を送信できる
- 送信時に必須項目と文字数の基本検証を行う
- 投稿データを審査待ちとして保存する
- 送信完了後に受付完了を画面表示する

## 対象外

- AI による自動審査
- 管理者向け審査 UI
- 番組台本への自動採用
- 音声読み上げの実行

## 想定ユーザー

- 一般投稿者
  - 番組に読まれることを期待してメッセージを送る

## ユーザーストーリー

1. 投稿者として、ラジオネームを入力したい。誰からの投稿か番組側に伝わるため。
2. 投稿者として、本文を入力したい。伝えたい話題やメッセージを送るため。
3. 投稿者として、送信完了を確認したい。正しく受け付けられたか不安を減らすため。

## 入力項目

| 項目 | 必須 | 型 | 制約 |
| --- | --- | --- | --- |
| radioName | 必須 | 文字列 | 1-30 文字 |
| content | 必須 | 文字列 | 1-300 文字 |

## バリデーション

- `radioName`
  - 前後空白は送信前に trim する
  - 空文字は不可
  - 30 文字超過は不可
- `content`
  - 前後空白は送信前に trim する
  - 空文字は不可
  - 300 文字超過は不可
- 共通
  - バリデーションエラー時は送信せず、項目ごとに文言を表示する
  - 二重送信防止のため、送信中はボタンを非活性にする

## 投稿ステータス

初期リリースでは以下の 3 状態を持つ。

| status | 説明 |
| --- | --- |
| pending | 投稿直後。未審査 |
| approved | 審査通過。番組生成の候補 |
| rejected | 審査却下。番組には使わない |

投稿作成時の初期値は `pending` とする。

## 最小画面要件

### 投稿フォーム

- 入力欄
  - ラジオネーム
  - 投稿内容
- 操作
  - 送信ボタン
- 表示
  - 項目単位のエラーメッセージ
  - 送信中状態

### 完了状態

- 「投稿ありがとうございました」などの受付完了メッセージを表示する
- 再投稿導線は任意とし、初回は必須にしない

## 保存データ

初期テーブルまたはコレクションは以下を想定する。

| フィールド | 型 | 備考 |
| --- | --- | --- |
| id | string | 主キー |
| radio_name | string | 表示用の投稿者名 |
| content | text | 投稿本文 |
| status | string | `pending` / `approved` / `rejected` |
| created_at | datetime | 投稿日時 |
| updated_at | datetime | 更新日時 |

## 受け入れ条件

- ラジオネームと投稿内容を入力して送信できる
- 未入力または文字数超過では保存されない
- 正常送信時、投稿は `pending` で保存される
- 正常送信時、ユーザーに受付完了が表示される
